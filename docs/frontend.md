# Angular UI

UI сохраняет операции, историю, atVersion и повтор команды с тем же Idempotency-Key.
Основная карточка читает только read model. Ответ команды хранится отдельно и не подменяет
карточку чтения: после commit write side может быть новее.

## Async CQRS

Экран показывает статус polling-обработчика и кнопки паузы/возобновления текущего backend.
Показываются write-side версия из comparison, версия проекции и число pending events.
Состояния подписаны как «Проекция догоняет» и «Модели совпадают». Пауза не кластерная.

После успешной команды UI выполняет отдельный GET. Если проекция отстаёт или отсутствует,
новые операции этого кошелька временно отключаются: expectedVersion берётся только из
показанной read model. Backend продолжает принимать команды независимо от этой блокировки UI.
PROJECTION_NOT_READY отображается как «Кошелёк создан, проекция ещё не готова».
Известные write-side версии хранятся по UUID кошелька и обновляются монотонно. Поэтому receipt
кошелька A не блокирует операции кошелька B; после возврата к A его известная неподтверждённая
версия сохраняется. Неизвестный результат команды также блокирует только её кошелёк; сохранённый
повтор другого кошелька остаётся доступным.

## Надёжность клиента

HttpClient получает ответы текстом, затем parseSafeJson проверяет безопасный диапазон
Java long до помещения данных в signals. Деньги форматируются через BigInt. Команды не
повторяются автоматически. Контекст выбора и отдельные состояния in-flight/queued для read
model, истории и статуса обработчика не позволяют одинаковым запросам выполняться параллельно.
Generation guards не позволяют ответу старого кошелька изменить новый экран. Запрос сравнения
сохраняет последний успешный снимок во время обновления; смена UUID начинает новый контекст
независимо от старого медленного ответа.

Comparison и read side обновляются управляемым интервалом без WebSocket. Polling объединяется
с ручным обновлением: занятый ресурс получает одну отложенную загрузку после текущей, а не
бесконечную очередь. После команды обязательное чтение не теряется. Управляющий POST pause/resume
блокирует кнопку, GET статуса с более старым epoch не может перезаписать его результат; после
POST выполняется актуальный GET и отображается PAUSE_REQUESTED, пока backend завершает порцию.
Статус обработчика запрашивается и без выбранного кошелька. При уничтожении компонента таймер
очищается. История сохраняет пагинацию 20 элементов и защиту от устаревших ответов. В localStorage
находятся только UUID недавних кошельков.

## Запуск

    cd frontend
    npm ci
    npm start

Dev proxy отправляет /api/** на http://127.0.0.1:28741. Production-сборка:
npm run build. Тесты и browser automation не добавляются и не запускаются.
