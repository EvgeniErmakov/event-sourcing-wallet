# Локальный Angular UI

UI в `frontend` предназначен для ручного изучения существующего Event Sourcing API.
Бэкенд, схема БД, миграции, события, fingerprint и границы транзакций не изменены.
Авторизации, списка всех кошельков, проекций, snapshots, SSR, WebSocket и NgRx нет.

Проверено 20.09.2026 по npm `dist-tags.latest` и peerDependencies:

## Точность денег и версий

UI поддерживает баланс от 0 до `9 007 199 254 740 991` копейки включительно
(`90 071 992 547 409,91 ₽`). Сумма команды — от 1 копейки до той же верхней границы.
Версии и курсор истории — безопасные целые JavaScript; версия состояния от 1 до
`9 007 199 254 740 991`, начальный курсор — 0. Новая команда разрешена только при
expectedVersion меньше верхней границы, чтобы её следующая версия также помещалась.

Ввод суммы — строка с точкой либо запятой, не более двух десятичных знаков.
Рубли и копейки разбираются через BigInt; умножения дробного `number` и округления нет.
Отрицательные суммы, ноль, экспоненциальная запись и лишние знаки отклоняются.
Пополнение, которое по текущей карточке вывело бы баланс за диапазон UI, блокируется.
Форматирование рублей также использует целочисленное деление BigInt.

Ответы HttpClient получает как текст. JSON reviver отвергает все небезопасные числа до
помещения DTO в signals. Java long за пределами диапазона не отображается как округлённый
баланс или версия и не используется для команд/пагинации. При таком ответе карточка
показывает явное ограничение; небезопасная страница истории целиком отклоняется.
Панель команды сохраняет исходный HTTP-текст, поэтому даже большой long там не теряет цифры.
Форматирование JSON применяется только к ответам с безопасными числами.
Backend-контракт остаётся прежним: JSON numbers, Java long/BIGINT.

## Команды и идемпотентность

Формы операций, открытия кошелька и просмотра версии связаны с `FormGroup` через `[formGroup]`.
Эта директива преобразует отправку формы кнопкой или Enter в `ngSubmit` и предотвращает
обычную перезагрузку страницы. Одного `[formControl]` на поле для вызова `ngSubmit` недостаточно.

Новая команда получает `crypto.randomUUID()` в Idempotency-Key. Создание также генерирует
UUID кошелька на клиенте. Все остальные команды берут expectedVersion из текущей карточки,
полученной последним успешным GET. Историческая карточка никогда не служит источником команды.

Последняя команда сохраняет метод, URL, строку JSON и ключ в памяти вкладки. Кнопка повтора
использует эту запись без изменений, даже если пользователь поменял сумму, выбрал другой
кошелёк или первоначальная версия давно устарела. При успехе receipt может содержать старое
состояние: после команды/повтора выполняется отдельное чтение актуального состояния.
Карточка не обновляется оптимистически и не подменяется ответом receipt.

Во время отправки повторные нажатия и новые команды заблокированы. При сетевой ошибке,
таймауте 20 секунд или 5xx результат считается неизвестным. Новые команды блокируются,
сохранённый запрос остаётся доступен для ручного повтора с прежним ключом. Автоматических
повторов списания или изменения expectedVersion нет. При VERSION_CONFLICT предлагается
обновить состояние; новая команда недоступна до успешного GET.

Запросы и ответы не записываются в localStorage. При неизвестном результате нельзя
перезагружать/закрывать вкладку до его разрешения: последняя команда живёт в памяти.
В localStorage находятся только до 12 UUID недавно открытых кошельков. Ошибка доступа
к хранилищу не блокирует API; локальный список тогда остаётся в памяти вкладки.

## Загрузки и история

Порядковые номера выбора и загрузки не позволяют старому GET заменить состояние нового
выбора, в том числе при переключении A → B → A. Исторический просмотр имеет свою защиту
и отдельное состояние. Ответ команды остаётся в панели последней операции с её UUID,
но не подменяет карточку другого кошелька.

История загружается по 20 событий через afterVersion/nextAfterVersion/hasMore.
При `hasMore=true` явно показано, что загружена только часть истории. «Загрузить ещё»
добавляет следующую страницу. При ошибке курсор не продвигается. После успешной команды
или обновления история начинается с первой страницы заново. Конец истории относится
к моменту чтения; автоматического polling и фоновой подписки нет.

UI показывает только события из ответа сервера. Описание обработки команды — объяснение
контракта, а не выдуманная пошаговая трасса выполнения. Текущее состояние и история читаются
отдельными запросами: при внешних конкурентных изменениях это не единый снимок БД.

## Запуск и проверки

Инструкции запуска и ручного использования — в [README](../README.md#angular-ui).
Dev proxy работает только при `npm start`; production-артефакт в `dist/wallet-ui/browser`
требует обычного статического сервера и маршрутизации `/api` к бэкенду на том же origin.
Глобальный CORS и публикация во внешнем сервисе не добавлялись.

Разрешены установка через `npm ci` и production-сборка `npm run build`.
Тестов, spec-файлов, тестовых targets, тестовых зависимостей и браузерных сценариев нет.
Поведение должно изучаться пользователем вручную; компиляция не заменяет такую проверку.
