# REST API кошельков

## Границы API

Все REST-контроллеры располагаются только в пакете `controller`, глобальный обработчик исключений — в `exception.api`. Контроллер зависит от WalletCommandService и WalletQueryService, не от реализаций и не от JDBC.

Контроллер принимает DTO, валидирует формат, преобразует запрос в команду и возвращает результат. Бизнес-правила проверяет Wallet; транзакцией управляет реализация сервиса. SQL, replay и обработку гонок в контроллер не переносить.

## Контракт

При рефакторинге сохранять существующие пути, JSON-поля, HTTP-статусы и Idempotency-Key. Суффикс Dto меняет имя Java-типа, но не JSON-контракт. Не вводить /api/v1, не переименовывать /close и не менять PUT на POST ради единого стиля.

Целевой контракт проекта:

| Метод и путь | Назначение |
|---|---|
| PUT /api/wallets/{walletId} | Создать кошелёк с заданным клиентом UUID |
| POST /api/wallets/{walletId}/deposits | Пополнение |
| POST /api/wallets/{walletId}/withdrawals | Списание |
| POST /api/wallets/{walletId}/close | Закрытие при нулевом балансе |
| GET /api/wallets/{walletId} | Текущее состояние из wallet_read_model; version = last_event_version |
| GET /api/wallets/{walletId}?atVersion=N | Состояние после события N |
| GET /api/wallets/{walletId}/events?afterVersion=0&limit=100 | Страница истории |
| GET /api/wallets/{walletId}/comparison | Независимое сравнение событий и проекции в одном снимке |

PUT здесь создаёт ресурс по известному URI; существующий кошелёк не перезаписывается. Повтор той же команды определяется Idempotency-Key. Закрытие добавляет WalletClosed, а не удаляет историю.

## DTO и валидация

Входные DTO — в dto.request, выходные — в dto.response; использовать неизменяемые records. Команды и события не переименовывать в DTO: у них другая ответственность.

Проверять UUID, обязательные поля, RUB, положительное целое amountMinor, целую expectedVersion и диапазоны параметров. Не округлять дробную сумму до целого. Денежные значения — копейки; примеры и JavaDoc должны явно указывать единицы.

Для изменяющих операций обязателен UUID-заголовок Idempotency-Key. Для существующего кошелька expectedVersion передаётся в запросе. Повтор успешной команды возвращает первоначальные статус и тело; для актуального состояния после других операций используется GET.

## Статусы и ошибки

| Статус | Смысл |
|---|---|
| 200 | Успешное чтение, пополнение, списание или закрытие |
| 201 | Кошелёк создан |
| 400 | Ошибка формы/типа/диапазона входных данных |
| 404 | Кошелёк или запрошенная версия отсутствует |
| 409 | Конфликт версии, ключа, существования или бизнес-состояния |
| 500 | Повреждённая история/проекция, неизвестный формат события, неожиданная ошибка |

Глобальный @RestControllerAdvice возвращает application/problem+json с ProblemDetail и устойчивым полем code. Сохранить коды из PROJECT.md и текущей реализации. Не вводить параллельный ErrorResponseDto. Не отдавать SQL, пароли, stack trace и детали JDBC.

В контроллерах не ловить бизнес-ошибки через try/catch. @ExceptionHandler и собственные исключения находятся в exception и его подпакетах.

## Пагинация и чтение

История ограничена limit: default 100, диапазон 1–500. Пагинация по stream_version; afterVersion >= 0. Возвращать items, nextAfterVersion и hasMore. Параметр atVersion ограничен существующими положительными версиями.

Пагинация HTTP-истории не должна обрезать replay: для восстановления текущего Wallet нужны все его события. Текущий GET читает проекцию основной БД; исторический GET восстанавливает префикс событий. Асинхронного обновления нет.

Добавлен диагностический /comparison; глобального CORS нет. Клиент использует ProblemDetail/code, сохраняет
исходную команду для повтора и отдельно читает текущее состояние после получения receipt.
Подробнее — [frontend.md](frontend.md).

README содержит последовательные примеры запросов и ответов, идемпотентности и конфликтов. Примеры не исполнять автоматически.

Swagger/springdoc не является обязательной зависимостью текущего этапа. Если уже подключён, сохранить совместимость и актуализировать описания; не добавлять только ради переноса документа. Авторизация, HTTP Basic, IAM и пользовательские роли не входят в этот учебный этап. Существующую защиту реального приложения при рефакторинге не удалять; правила — в security.md.

## Сравнение моделей и отсутствующая проекция

`GET /api/wallets/{walletId}/comparison` возвращает HTTP 200:

```json
{
  "eventState": {"walletId":"11111111-1111-4111-8111-111111111111","balanceMinor":10000,"currency":"RUB","status":"ACTIVE","version":2},
  "readModel": {"walletId":"11111111-1111-4111-8111-111111111111","balanceMinor":10000,"currency":"RUB","status":"ACTIVE","version":2},
  "matches": true
}
```

Сравниваются UUID, баланс, валюта, статус и версия. Чтение — одна read-only REPEATABLE READ
транзакция. Отсутствующая проекция известного кошелька даёт readModel=null и matches=false;
другие реальные расхождения возвращаются с обоими состояниями и matches=false. Это диагностический
результат, а не ошибка транспорта. Неизвестный кошелёк даёт 404 WALLET_NOT_FOUND.

Обычный GET при отсутствии строки для существующего потока возвращает 500
PROJECTION_INTEGRITY_ERROR. Он не делает replay/backfill. Неизвестный поток даёт прежний 404.
Ошибка проектора при записи также даёт 500 PROJECTION_INTEGRITY_ERROR и rollback всей команды.
Тела и статусы прежних команд, в том числе сохранённые receipts, не меняются.
