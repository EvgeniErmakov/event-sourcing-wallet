# Безопасность учебного кошелька

Текущий этап — локальный Event Sourcing + синхронный CQRS, без авторизации и новых
бизнес-операций. Не добавлять Spring Security или внешние системы доступа в рамках этапа.
Такой API не предназначен для публикации в недоверенную сеть без отдельной работы по защите.

SQL параметризован; пользовательские UUID, суммы и версии не подставляются в текст SQL.
EventSerializer использует явный реестр типов и версий, а не имена произвольных Java-классов.
Повреждённые события не пропускаются. Сервер не принимает проекцию или баланс клиента как
источник истины для команды: Wallet восстанавливается из сохранённых событий.

Ответы ProblemDetail не раскрывают SQL, stack trace, credentials или неизвестный payload.
Параметры подключения передаются через DB_URL/DB_USERNAME/DB_PASSWORD; .env не коммитится.
Учебные значения wallet/wallet применимы только к локальной БД. Не логировать секреты,
полные тела команд и массовые выгрузки обеих моделей.

GET /comparison — только чтение. HTTP-endpoint восстановления, удаления проекции и паузы
проектора отсутствует. Приложение не удаляет события, receipts или volumes и не исправляет
данные при GET скрытно. Учебный запуск рассчитан на чистую БД, которую пользователь готовит
самостоятельно; Liquibase создаёт схему при обычном старте. CLI-восстановления нет.

Frontend использует Angular interpolation, текстовый HttpClient и parseSafeJson; значения
long вне безопасного диапазона не используются как округлённые деньги или версии.
Глобальный CORS не добавлен; локальные запросы идут через dev proxy на том же origin.
