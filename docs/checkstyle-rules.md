# Форматирование и правила Checkstyle

Этот файл определяет желаемый стиль. Он не утверждает, что в репозитории уже есть checkstyle.xml или подключён соответствующий Gradle plugin. В текущем рефакторинге не вводить новый обязательный инструмент проверки; существующую конфигурацию адаптировать только при необходимости для Java 25.

## Основные правила

| Правило | Требование |
|---|---|
| Кодировка | UTF-8 |
| Отступ | 4 пробела, без табов |
| Длина строки | До 140 символов; неизменяемые URL и строки с техническим форматом могут быть исключением |
| Типы | Один top-level тип в файле; имя файла соответствует типу |
| Имена | UpperCamelCase/lowerCamelCase/UPPER_SNAKE_CASE по code-style.md |
| Литерал long | Заглавная L |
| Массивы | String[] args |
| Объявления | Одна переменная на объявление |
| Операторы | Один самостоятельный оператор на строку |
| Фигурные скобки | Открывающая на строке объявления; скобки обязательны для if/else/циклов |
| Аннотации классов/методов | Каждая на отдельной строке |
| Импорты | Сначала static, пустая строка, остальные; группы по алфавиту; без неиспользуемых и wildcard |
| Переносы | Точка и бинарный оператор в начале продолжения; запятая в конце предыдущей строки |
| Пустые строки | Одна между методами и логическими группами |
| Перегрузки | Рядом |
| Модификаторы | Стандартный порядок, например public static final |
| finalize | Не переопределять |

Вложенные отступы продолжения оформлять последовательно, обычно +4 или +8 относительно объявления. Не изменять строковые литералы, SQL, event_type или JSON-ключи ради форматирования.

## Java 25, records и sealed types

- Разрешены records, sealed interface, pattern matching и switch expressions без preview.
- Для исчерпывающего switch по закрытому набору типов/enum не требовать лишний default.
- Для входного строкового event_type предусмотреть явную ошибку неизвестного типа. Отсутствие default в исчерпывающем Java-switch не означает разрешения пропускать неизвестные события из БД.
- Пустой обработчик события или default, который молча ничего не делает, запрещён, если это скрывает неподдерживаемую историю.
- Records и интерфейсы без тела не нуждаются в фиктивных комментариях ради запрета пустых блоков.
- Не требовать JavaBean getters/setters от record.

## Методы и лямбды

Лимиты 20 строк лямбды и 20–30 строк метода — рекомендации. Допускаются обоснованные исключения для явной транзакции, mapping и обработчика конечного набора событий. Не менять поведение и границы транзакций ради счётчика строк.

## JavaDoc

Для значимых public/package-private типов и методов — описание назначения и контракта. Порядок тегов: @param, @return, @throws, @deprecated. Перед тегами пустая строка; пустые описания тегов запрещены. Конкретные требования к содержанию — в code-style.md.

## Исключения и конфигурация

Пустой catch не разрешается только потому, что параметр называется expected. В проекте нет тестов; ошибки не скрывать. SuppressWarnings допускается лишь с локальным объяснением. Не отключать все проверки ради одного несовместимого правила; не считать форматирование доказательством корректности Event Sourcing.

## Синхронный CQRS

Те же правила применяются к командному/query-сервисам и проектору. Не разбивать транзакцию
на независимые операции ради лимита длины метода. SQL CAS и формат fingerprint не менять
ради стиля; TransactionTemplate callback сравнения должен оставаться единым снимком.
