# Спецификация и текущий этап

Полные требования находятся в [корневом PROJECT.md](../PROJECT.md).
Правила разработки — в [AGENTS.md](../AGENTS.md), запуск и учебные примеры — в [README](../README.md).

Первая версия реализована на сохранённом стеке: Java 25 без preview, Spring Boot 4.0.8,
Gradle 9.5.1, PostgreSQL 17.11, Spring MVC/JDBC и Liquibase.

Реализованы чистый Java-домен, decide/apply/rehydrate, четыре команды, текущий и исторический
GET, пагинация истории, явный реестр форматов событий, атомарный CAS версии и постоянные receipts.
Состояние восстанавливается из событий; таблицы текущего баланса нет.

## Уточнения реализации

- `WalletService` задаёт READ COMMITTED и REQUIRES_NEW; успех возвращается после commit.
- `JdbcEventStore.load` одним LEFT JOIN читает весь поток и техническую версию в одном снимке.
  Версия агрегата выводится из числа применённых фактов; метаданные лишь проверяют целостность.
- Три адресных `ON CONFLICT ON CONSTRAINT ... DO NOTHING` распознают только ожидаемые
  коллизии: PK потока, UNIQUE позиции события, PK receipt. Нулевой результат прерывает
  транзакцию; сервис ищет результат конкурента только после rollback в новой транзакции.
  Неожиданные SQL-ошибки возвращаются как 500, не маскируются под 409.
- Повторное чтение receipt также выполняется после доменного отказа по версии/состоянию.
  Если конкурент ещё не зафиксирован, возвращается исходный отказ без автоматического повтора команды.
- Все успешные команды порождают один факт. UUID и время создаются вне replay через UUID/Clock.
- JSON обрабатывает Jackson 3 из BOM Boot. Дробные/строковые числа, неизвестные поля и
  сокращённые UUID отвергаются. Неизвестные типы и schemaVersion дают CORRUPT_HISTORY.
- YAML master подключает три последовательных changeset в `001-wallet.sql`.
  Применённые changeset не изменяются; следующие изменения требуют новых миграций.
- Исторический GET загружает полный поток и применяет префикс. Replay имеет стоимость O(N).

Сборка bootJar и обычный запуск с применением трёх миграций выполнены.
Тестов нет по запросу пользователя; API-сценарии и SQL-примеры автоматически не выполнялись.
Старт приложения не доказывает корректность конкурентного поведения.
Snapshots, проекции, upcasters и остальное за пределами первой версии не реализованы.
